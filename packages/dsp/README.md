# @wake-studio/dsp

Platform DSP package (ADR-032): FFT, STFT/ISTFT, window functions, Slaney mel
filterbank + melSpectrogram, resample and level-meter helpers.

Pure TypeScript with **no DOM and no wasm dependencies** - every module runs in
any JS context (Node, browser, Web Worker, AudioWorklet).

## Why this package exists

The DSP code used to live in three places (afe-graph viz, PLiX mel front-end,
few-shot quality checks) as hand-written radix-2 FFTs with no cross-check
against a reference implementation. This package:

1. delegates the FFT core to **fft.js** (MIT, indutny) - a battle-tested pure-JS
   radix-4 FFT (the same one used by web-audio pipelines), fully auditable and
   AudioWorklet-safe.
2. locks the higher-level behavior (STFT framing, windowing, mel filterbank)
   against **conformance fixtures** generated from scipy / numpy, committed to
   `tests/fixtures/`. Any change that silently drifts the numeric behavior
   fails CI.

## Layout

| File | Contents |
|---|---|
| `src/fft.ts` | `createFft` / `fft` / `ifft` - thin wrapper over fft.js (interleaved <-> separate real/imag). |
| `src/stft.ts` | `stft` / `istft` - frame framing, windowing, zero-pad, magnitude or complex output, overlap-add reconstruction. |
| `src/windows.ts` | Hann (periodic + symmetric), Hamming, Blackman, `applyWindow`. |
| `src/mel.ts` | `buildMelFilterbank` (Slaney triangular) + `melSpectrogram` (raw or log). |
| `src/spectrum.ts` | `computeSpectrum` (FFT_SIZE/SPECTRUM_BINS/HANN_WINDOW) + `sineWave`/`constant`/`argMax` test helpers (migrated from afe/graph). |
| `src/level.ts` | `levelDb`, `peakDbfs`, `rmsDbfs`, `isClipped`, `frameRms`, `applyGain`, `estimateSnrDb`, `downsample48to16`, `downsampleForViz`. |
| `tests/conformance.test.ts` | Diff against scipy/numpy fixtures. |
| `scripts/gen-conformance-fixtures.py` | Regenerate fixtures (Python 3 + scipy). |

## Conformance fixtures

The fixtures in `tests/fixtures/*.json` are generated by
`scripts/gen-conformance-fixtures.py` (needs a Python env with `numpy` +
`scipy`). They are committed, so the JS tests run without Python.

To regenerate after a deliberate behavior change (should be rare and
reviewed):

```bash
python3 -m venv /tmp/dsp-venv && /tmp/dsp-venv/bin/pip install numpy scipy
/tmp/dsp-venv/bin/python scripts/gen-conformance-fixtures.py
```

References locked by the fixtures:

- **FFT** - `scipy.fft.fft` (sizes 8/16/256/1024; impulse, Nyquist, mixed sine).
- **STFT** - `scipy.signal.stft` (window-sum normalized amplitude; scipy
  convention).
- **Mel** - the PLiX front-end math (`plixkws/backbone.py::Backbone`,
  sample_rate=16000, f_min=60, f_max=7800, n_mels=64, win_length=400,
  hop_length=160, n_fft=1024), raw magnitude (no log), 98 frames for 16000
  samples. This is the exact contract the PLiX ONNX graph expects.

## Conventions

- STFT magnitude uses **scipy amplitude normalization** (`1/sum(window)`),
  matching `scipy.signal.stft` and visualization expectations.
- Mel spectrogram uses **raw |FFT|** (no window-sum normalization) and periodic
  Hann over `winLen` with zero-pad to `nfft` - this matches the PLiX reference
  math exactly (the ONNX graph applies `log(mel + 1e-6)` itself).
- `frames = floor((len - frameLen) / hop) + 1` - exact framing, no trailing
  partial frame.

## Performance note

FFT core is pure JS (no SIMD/wasm). For real-time AFE visualization (256-pt
FFT per frame) this is far below budget (~0.008 ms/FFT). If a future stage
(AEC3, beamforming) needs more, the `createFft` seam allows swapping in a
SIMD/wasm backend without touching call sites.
